# Лабораторная работа №1. Выбор и обоснование темы индивидуального задания

## Тема

**Система прогнозирования матчей** — веб-сервис, прогнозирующий исход
матчей по киберспортивной дисциплине Dota 2 на основе статистики команд,
полученной из открытого публичного API [OpenDota](https://www.opendota.com/).

## Почему выбрана эта тема

1. **Естественно покрывает все обязательные архитектурные компоненты
   курса.** Задача требует полноценного клиент-серверного взаимодействия
   (фронтенд запрашивает список команд и строит прогноз), хранения
   исторических данных (матчи, команды, прогнозы) в БД, нетривиальной
   вычислительной логики (расчёт рейтинга и вероятности победы — не
   CRUD-операция, а полноценный алгоритм) и асинхронной работы (загрузка
   данных из внешнего API не должна блокировать сервис). Это не надуманное
   требование «для галочки» — без каждого из компонентов система не будет
   работать корректно.

2. **Данные реальны и общедоступны.** OpenDota API отдаёт статистику
   профессиональных команд и матчей в JSON без необходимости в API-ключе
   и без риска нарушить условия использования сайта (в отличие от
   скрапинга HLTV, у которого явно выраженная защита от автоматических
   запросов). Это позволяет строить прогноз не на синтетических, а на
   актуальных данных, обновляемых по требованию пользователя.

3. **Предметная область понятна и проверяема.** Результат работы системы
   (вероятность победы команды) — интерпретируемая величина, которую легко
   продемонстрировать на защите: можно сравнить прогноз с реальным
   результатом уже сыгранных матчей и обсудить, почему модель ошиблась или
   оказалась права.

4. **Расширяемость.** Базовая модель (Elo-рейтинг + недавняя форма)
   осознанно выбрана простой, чтобы уложиться в сроки лабораторных работ,
   но архитектура (отдельный функциональный модуль, обращающийся к нему по
   сети) позволяет в дальнейшем заменить или дополнить алгоритм прогноза
   (например, логистической регрессией на большем наборе признаков) без
   изменения остальной системы — это будет проговорено как один из
   аргументов при обосновании архитектурных решений (ЛР №2).

## Границы задания

В рамках курса реализуется:

- регистрация/авторизация пользователей с обязательной двухфакторной
  аутентификацией (TOTP);
- загрузка и хранение данных о командах и матчах Dota 2 с OpenDota;
- расчёт Elo-рейтинга и «формы» команды по истории матчей;
- построение прогноза исхода матча между двумя произвольными командами;
- веб-интерфейс для всех перечисленных сценариев.

Не входит в рамки задания (и не заявляется как реализованное):

- получение официального расписания предстоящих профессиональных матчей
  (бесплатный OpenDota API его не предоставляет — см. раздел «Известные
  ограничения» в [README.md](../README.md));
- взаимодействие с аппаратным обеспечением (опциональный компонент
  архитектуры курса, не применим к веб-сервису прогнозирования);
- обучаемая ML-модель — используется прозрачный статистический метод
  (Elo), что осознанно упрощает объяснение и защиту результатов на зачёте.
